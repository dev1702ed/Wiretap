## 0. What this project is — read before designing anything

DCP captures data lineage at the transport layer — inside the database and Kafka
client libraries — instead of from application-layer plugins. **The repo is a
measurement instrument, not a product.** Its purpose is to produce numbers
showing that application-layer lineage (OpenLineage and similar) structurally
misses data movement. `/benchmarks` is the product; the SDK and backend are
apparatus.

Consequences for how you work:

- **Correctness over features.** A wrong edge corrupts the precision/recall
  numbers the project exists to produce. Prefer fewer capabilities, tested.
- **No claim without a number.** Every number in docs must come from a
  committed script whose output you paste verbatim. Never hand-type a result.
- **Never weaken a test to make it pass.** If a test looks wrong, say so in the
  report and leave it failing.

## 2. Event model — invariants you must preserve

These are deliberate decisions, and tests enforce most of them. Do not "fix" them.

| Rule | Why |
|---|---|
| One event per dataset touched: `op` is `read` or `write` | Spec |
| `trace_id` is constant across one multi-hop flow, including across processes | Multi-hop claim |
| `parent` is a **list** of upstream `edge_id`s (`[]` at origin) | Fan-in is real |
| Reads within one statement are never parented to each other | A JOIN's tables don't feed each other |
| A write's parents are the reads in **its own statement** if any; otherwise the latest read of each dataset earlier in the flow ("job-level"); otherwise inbound context | Precise where SQL names its sources, job-level only where data passed through the application |
| Postgres reads have `parent: []` in v1 | Rows carry no per-record metadata, so a later reader cannot know who wrote the rows |
| A Kafka consume read is parented to the producer's write edge, carried in the `dcp-context` record header | The only attested cross-process link in v1 |
| The Kafka consumer does **not** call `set_inbound` | Otherwise every later DB read would be wrongly parented to the Kafka producer |
| The SQL comment carries `dcp_trace` only, never parents, and is opt-in (`init(propagate_sql=True)`) | Parents vary per call and would defeat psycopg's prepared-statement cache; their URL-encoding would inject `%` into parameterised queries |
| DDL emits nothing; statement classification is a whitelist | CREATE/DROP/ALTER move no data |
| Every capture path catches exceptions broadly and logs at debug | Monitor-only: DCP must never break the caller |

Ruff in this repo enforces an extended rule set (including `BLE001`, `S110`,
`FURB`, `RUF022`, import sorting). A deliberate broad `except` needs
`# noqa: BLE001 — <reason>` and a `_log.debug(..., exc_info=True)`, never `pass`.

Python floor is **3.10**; CI runs 3.10 and 3.12. Don't use 3.11+ APIs
(`datetime.UTC`, `typing.Self`, `uuid.uuid7`, etc.).

## Part B — P3: queryable lineage

Build the backend: store every event, derive the lineage graph, answer queries.
The key constraint comes from `backend/app/ingest.py`: **the SQLite event log is
the source of truth; the graph is a derived view that must be rebuildable
exactly by replaying the log.** Benchmark reproducibility depends on it.

### B1. `backend/app/graph.py` — the graph

`build(events)` returns a graph object. Its contract is already fixed by
`sdk-python/tests/test_ground_truth.py`; do not change that contract. Provide an
incremental form too (`add(event)`), so ingest can fold events in; `build` is a
fold over `add`. Use **networkx** for traversals.

Dataset key = `(namespace, name)`. Semantics, exactly:

| Method | Definition |
|---|---|
| `datasets()` | Every `(namespace, name)` that appears in any event |
| `dataset_edges()` | For each **write** W, for each parent id P that resolves to a **read** R: `(R.dataset, W.dataset, W.job.name)` |
| `run_edges()` | For each **read** R, for each parent id P that resolves to a **write** W: `(W.job.name, R.job.name, R.dataset)`. In v1 these only arise from Kafka headers |
| `upstream(ds)` | **Run-level provenance.** Start from every write event on `ds`, walk `parent` links transitively over events, and collect the dataset of every event reached, excluding `ds` itself |
| `dataset_upstream(ds)` | **Dataset-level** ancestors of `ds` in the `dataset_edges` graph. This is the baseline that `upstream` is compared against |
| `downstream(ds)` | Blast radius: dataset-level descendants in the `dataset_edges` graph. Deliberately dataset-level — impact analysis wants recall |
| `dangling_parents()` | Parent ids referenced by some event but never seen. Report this; don't crash on it |

Requirements:

- **Order-independent.** Events can arrive in any order: HTTP emitters in
  different processes race. A child can arrive before its parent. The result
  must be identical for any permutation of the same events. Test it.
- **Cycle-safe.** `UPDATE t ... WHERE id IN (SELECT id FROM t)` produces a
  self-loop. Every traversal must terminate. Test it.
- `upstream` must **never** fall back to dataset-level reachability. The
  `topic_fan_in` answer key exists precisely to catch that.
- **Do not infer store-mediated links** (a write to a table followed by a later
  read of it by another job). That's a known v1 limitation, and inference would
  silently mix inferred edges into attested ones. Mention it in the report as
  follow-up work.

### B2. `backend/app/store.py` — SQLite append-only log

- stdlib `sqlite3`. Database path from the env var `DCP_DB_PATH`, defaulting to
  `dcp_events.db` (`*.db` is already gitignored).
- `append(event)` stores the event JSON with an autoincrement id.
- `replay()` returns every event in ingest order.
- Tests use `tmp_path`, never the default path.

### B3. `backend/app/identity.py` — dataset identity

Implement `resolve(namespace, name)` **conservatively**: deterministic,
lossless normalisation only (strip surrounding whitespace, lowercase the scheme
and host). Do **not** resolve DNS or merge hosts.

In particular, do not canonicalise `localhost`. It's relative to the machine
that emitted the event, so `postgres://localhost:5432` from two different hosts
refers to two different databases. Merging them would corrupt precision.

Record this decision and its trade-off — fragmentation risk vs. false merges —
in `docs/decisions/identity.md`; the stub's docstring asks for exactly that.
Ground-truth namespaces (`postgres://localhost:5432`) must come through
unchanged.

### B4. `backend/app/ingest.py`

Validate each event against `spec/envelope.schema.json` (`jsonschema`), append
it to the store, then fold it into the in-memory graph. Validate the whole batch
before appending anything, so a batch is accepted or rejected atomically.

### B5. `backend/app/main.py` — API

Dataset keys contain `://` and `/`, so pass them as **query parameters**, not
path segments. This deviates from the roadmap's `/downstream/{dataset}`; note
that in the report.

| Endpoint | Behaviour |
|---|---|
| `POST /events` | Body is one event or a JSON array. Returns `{"accepted": n}`; `422` if any event is invalid, with nothing stored |
| `GET /upstream?namespace=&name=&level=run` | `level=run` (default) → `upstream()`; `level=dataset` → `dataset_upstream()` |
| `GET /downstream?namespace=&name=` | `downstream()` |
| `GET /graph` | Datasets, dataset edges, run edges, event count, dangling-parent count |
| `GET /health` | Keep as is |

Unknown dataset → `404`. On startup, rebuild the graph by replaying the store
(use FastAPI lifespan). Make the store path injectable for tests.

### B6. SDK emitters (`sdk-python/dcp/emitters/`)

- **`FileEmitter`** (`file://path`): JSONL, one event per line, thread-safe
  (lock). This is the event of record for benchmarks.
- **`HTTPEmitter`** (`http://host:port`): POSTs JSON arrays to `{endpoint}/events`
  using **stdlib `urllib` only** — the SDK takes no new dependencies. It runs a
  background daemon thread with a bounded queue and batches events.
  **`emit()` must never block the caller.** When the queue is full, drop the
  event, increment a `dropped` counter, and log a warning. The emitter stub
  leaned towards "block briefly", but `emitters/__init__.py` makes non-blocking a
  hard requirement for the <1 ms p99 target, so non-blocking wins. Record this
  under Assumptions. Retry a failed POST a few times with backoff, then drop and
  count it. `flush(timeout)` waits for the queue to drain.
- `config.init()` parses `console`, `file://…`, `http://…`. `marquez://` raises
  `NotImplementedError("P4")`; anything else raises `ValueError`. For the file
  and HTTP sinks, register `shutdown` with `atexit`, so a script that never
  calls `dcp.shutdown()` still delivers its events. Dark-zone scripts are exactly
  that kind of script.

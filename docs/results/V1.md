## What v1 is

DCP captures data lineage at the transport layer, inside the Postgres (psycopg 3) and
Kafka (confluent-kafka) client libraries of a Python process, so a script, a notebook or a
glue job is captured with no lineage code in it (`dcp-instrument`). Each event records
the dataset read or written and the exact upstream events that fed it, and a trace
context carried in a Kafka record header links a consumer's events to the producer's
across processes. A backend rebuilds a queryable lineage graph from the event log, and a
bridge translates the events into OpenLineage, with a `dcp` facet that keeps what
OpenLineage's core model cannot express. The repository is a measurement instrument: its
benchmarks measure, live and against answer keys, how much data movement
application-layer lineage misses, how accurate DCP is (including where it fails), and
what it costs per call. v1 ships the capture SDK, the backend, the bridge, those
benchmarks, and the evidence pack the paper is written from.

404 means no project of that name today; PyPI can still refuse a name at
upload.
